# Save conversations

There are two ways to keep a conversation:

- **Let the session keep it.** Set `history: true`. The session stores every conversation,
  lists them on the chat's own history page, and opens the one the user selects.
- **Store it yourself.** Call `session.save()` to get a `PiSnapshot` and write that object
  to `localStorage`, `chrome.storage`, a database, or your own backend.

## Built-in history

```ts
import { browserStorage, createPiSession } from "agentak/pi";

const session = createPiSession({ history: true, storage: browserStorage() });
```

This adds a clock button to the chat header. It opens a page that lists the stored
conversations, marks the live one, and gives each row a button to forget it. Selecting a
conversation replaces the session state in place, so the chat is not unmounted and your app
swaps nothing.

The session stores a conversation in the same `PiStorage` as the API keys. The default
store is memory, which the browser clears on reload. Pass `browserStorage()` for
`localStorage`, or your own `PiHistory` object for another store:

```ts
const session = createPiSession({ history: myOwnStore });
```

What the session does when `history` is set:

- It opens on the newest stored conversation, so a reload continues where the user stopped.
  A `snapshot` option takes priority.
- It writes the conversation each time the model finishes, and again when the model names
  the conversation. `dispose()` writes the last state.
- **New conversation** stores the current one before it clears the chat.
- It keeps 20 conversations. Older conversations are removed, and also when the store is
  full.
- It never stores an empty conversation.

History is off by default. Nothing is stored unless you ask for it.

## Save and restore

```ts
import { createPiSession, readPiSnapshot, type PiSnapshot } from "agentak/pi";

function loadSnapshot(): PiSnapshot | undefined {
  const stored = localStorage.getItem("chat");
  if (!stored) return undefined;

  try {
    return readPiSnapshot(JSON.parse(stored));
  } catch {
    return undefined;
  }
}

const session = createPiSession({ snapshot: loadSnapshot() });

let saveTimer: ReturnType<typeof setTimeout> | undefined;
const unsubscribe = session.subscribe(() => {
  clearTimeout(saveTimer);
  saveTimer = setTimeout(() => {
    localStorage.setItem("chat", JSON.stringify(session.save()));
  }, 500);
});

// When the app no longer needs this conversation:
// clearTimeout(saveTimer);
// unsubscribe();
// session.dispose();
```

A streamed answer sends many updates. The short delay avoids writing the full conversation
for every update.

`save()` is safe to call while the model is answering. It only includes messages that are
complete.

## Snapshot fields

| Field           | Type                         | Description                                            |
| --------------- | ---------------------------- | ------------------------------------------------------ |
| `version`       | `number`                     | Snapshot format version. `readPiSnapshot()` checks it. |
| `messages`      | `AgentMessage[]`             | Transcript in the Pi agent format.                     |
| `provider`      | `string \| undefined`        | Provider used by the conversation.                     |
| `model`         | `string \| undefined`        | Model used by the conversation.                        |
| `thinkingLevel` | `ThinkingLevel \| undefined` | Thinking level used by the model.                      |
| `title`         | `string \| undefined`        | Model-generated title, when enabled.                   |

The snapshot stores more than the transcript. This lets Agentak reopen the conversation
with the provider, model, and thinking level that created it. These values take priority
over the browser's saved defaults for that conversation.

## Read stored data safely

Pass stored data through `readPiSnapshot()` before creating a session. It checks the
snapshot version and confirms that `messages` is an array. It does not deeply validate
each message or optional field. Validate untrusted data before you use it.

`readPiSnapshot()` returns `undefined` when the version is unsupported or `messages` is not
an array. Passing that result to `createPiSession()` starts a new conversation instead of
throwing an error. Catch `JSON.parse()` errors separately, as shown above.

Agentak also repairs a transcript when it opens one:

- It removes a tool call that has no result. Providers reject an incomplete tool call.
- It removes a failed turn at the end of the transcript.
- It does not restore tool approvals. The user must approve a new call again.

## Store several conversations

Use `history: true` unless your app must control the storage. If it must, store one
snapshot for each conversation and switch between them with `restore()`:

```ts
session.restore(loadSnapshot(id)); // the transcript, provider, model, and level
```

`restore()` replaces the state of the running session, so the chat stays mounted. It stops
a turn that is still running, and it stores the current conversation first when the session
keeps its own. Call `restore()` without an argument to start an empty conversation.

You can also create a new session for each conversation and pass it to `ChatPanel` or
`AgentChat`. Dispose of the session you replace.

The chat UI lists conversations only when the session reports them. A session that stores
nothing shows no history button. See
[custom agents](custom-agents) for the `history`, `openConversation`, and
`forgetConversation` members of `ChatSession`.

## Titles

By default, Agentak uses the first user message as the title. Set `generateTitle` on
`ChatPanel` or `createPiSession()` to ask the model for a shorter title:

```tsx
<ChatPanel session={session} generateTitle />
```

This uses one extra model request after the first answer. If the request fails, the title
from the first message stays in place.
